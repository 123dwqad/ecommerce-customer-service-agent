# 电商智能客服 Agent — 项目表述与实现边界

日期应填写实际开发时间；原文的 `2026.01 - 2026.07` 只有在符合真实经历时才保留。电商知识库 RAG 工具于 2026 年 10 月接入。

## 建议使用的项目介绍

针对电商售前商品咨询、订单物流查询及售后服务中的重复咨询，搭建电商智能客服 Agent 原型，整合本地商品资料、版本化售后政策、知识库 RAG 与模拟订单接口，支持多轮咨询、业务查询与受控操作。

1. **Agent 架构设计**：基于 LangGraph 编排意图识别、上下文解析、受控工具调用和结构化回复；在可选大模型模式下，通过 ReAct 与只读工具处理商品咨询，维护当前商品、订单和待确认事项，记录工具执行轨迹。
2. **售后规则与订单联合校验**：通过鉴权接口读取订单状态、签收时间和商品属性，按订单绑定的政策版本及适用范围匹配规则，由 Python 规则服务完成申请资格校验，返回处理建议与条款依据；对信息缺失、规则不匹配及超权限诉求引导澄清或人工处理。
3. **知识库 RAG 检索**：对商品说明、FAQ、店铺服务与售后流程文档做多策略切块（条款/步骤/表格/递归）与父子块索引，检索链路由历史压缩、Query 改写、Step Back、BM25/ES + 向量多路召回与 RRF 融合组成，回答附带来源与位置；资格判定仍走规则服务，RAG 只负责解释流程与政策文本，见 `commerce_rag.md`。
4. **会话记忆与隐私管控**：支持 Redis 保存短期对话和业务上下文，并按登录会话与会话编号隔离；按用户保存品类及回复偏好。订单查询会验证登录身份和订单归属，只向 Agent 提供当前任务所需字段；真实业务接入时，地址及联系方式仅在办理确有需要、且用户授权后通过鉴权接口读取，并做脱敏和最小化传递。当前演示版不向 Agent 返回地址和联系方式。
5. **业务操作与异常处理**：取消订单、创建售后申请前生成绑定订单版本的确认记录，提交时复核权限和状态，通过事务与幂等记录控制重复写入；为无匹配资料、接口超时、模型格式异常及上下文歧义设置澄清、有限重试与回退策略，使用请求标识关联日志。
6. **评测迭代闭环**：建立覆盖商品咨询、订单物流、售后、越权及多轮追问的回归集，校验意图、预期订单参数、任务结果和越权拦截；记录耗时并根据失败案例调整规则、上下文解析和工具路由。

## 项目成果

基于覆盖商品咨询、订单物流、售后、越权及参数边界的 115 条本地用例评测（120 个意图步骤）：规则与模型混合链路意图识别准确率 100%（120/120）；工具参数准确率 100%（85/85，含订单号、商品、数量、区域及规则主题），含糊/缺参拦截 100%（9/9）；任务完成率 86.96%（100/115）；越权拦截率 100%（6/6）；平均响应延迟 1.10 秒（P95 10.03 秒）。本轮规则识别覆盖 113 步，模型成功返回 7 步；属本地模拟评测，未启用 RAG，不代表生产表现。

## RAG 的边界

规则判定（库存、优惠、运费、发货时效、改地址、取消、发票、保价、物流停滞、无理由退货）必须精确匹配政策版本、商家、渠道和商品类型，不能仅依赖语义相似度选中一个文本片段，因此这些路径不使用 RAG，由 Python 规则服务按订单绑定版本判定。

RAG 用于商品说明、FAQ、店铺服务与售后流程文档的检索与解释（`rag_search` 只读工具），支持文档解析、多策略切块、父子块、Query 改写、混合召回与 RRF 融合；无外部模型时离线降级为本地哈希向量 + BM25。索引未就绪时自动后台构建，当前请求回退关键词检索。详见 `commerce_rag.md`。

## 可以讲与不能讲的内容

新增可选能力：通过外部 API 实现语音转写输入与电商图片分析，分别配置服务地址、模型和密钥。转写先由用户检查再发送；图片分析只读，不自动关联订单或触发写操作。可以描述接口与交互实现，真实模型效果需要配置服务后评测。

| 内容 | 当前实现 |
| --- | --- |
| LangGraph 对话流程 | 已实现 |
| ReAct 商品咨询 | 可选代码路径；需模型 Key，离线测试不代表真实模型评测 |
| 意图识别 | 规则实现，未训练分类模型 |
| 规则版本与依据追踪 | JSON 文件、订单版本绑定、范围匹配 |
| 订单与物流接口 | 模拟数据，持久化到 SQLite/MySQL |
| 售后处理 | 初步资格判断与申请提交，未实现真实退款 |
| 人工客服 | 本地排队记录，未连接客服平台 |

| RAG / 向量检索 | 已实现 `rag_search` 只读工具（演示文档，本地 Qdrant）；不能声称生产检索准确率 |

## 修改政策的示例

要模拟新的店铺活动规则，复制一条政策为新版本，例如 `RETURN-DEMO-v2`，修改适用范围和期限，并让新订单绑定 v2。旧订单继续绑定 v1。政策更新后重启两个服务，确保 API 和 MCP 使用同一份配置。

规则文件目前不支持在线审批、灰度或不可变版本存储，这些是后续扩展点。涉及真实平台售后条件时应以真实商家政策为准，不能把演示值当成通用承诺。
