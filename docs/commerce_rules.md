# 电商规则清单

共 10 类规则：原有无理由退货，加上 9 类售前与售中规则。均为演示店铺自行配置的数据，不是对真实商家、物流或法定权利的承诺。

| 场景 | 判断内容 | 可直接尝试的问题 |
| --- | --- | --- |
| 库存与限购 | 单笔上限 5 件；购买量不能超过演示库存 | `P100 买6件有货吗` |
| 优惠与叠加 | 非定制商品满 200 减 20；运费不计门槛；不可叠加 | `P100 买2件能用优惠券吗` |
| 运费与范围 | 普通区域满 99 包邮、否则 8 元；新疆/西藏 20 元；港澳台/海外不配送 | `P200 买1件普通区域包邮吗` |
| 发货时效 | 普通商品付款后 48 小时、定制 120 小时；超时引导人工 | 选择待发货订单后问 `什么时候发货` |
| 收货信息修改 | 未发货可申请；已发货不能直接改；只查资格，不修改地址 | 选择订单后问 `可以改地址吗` |
| 订单取消 | 未发货可申请；定制开始制作后拦截；提交时再次校验 | `这单能取消吗`（只查规则），`取消订单`（生成确认卡片） |
| 发票 | 已付款且未取消；按历史商品实付金额；已有发票不重复开具 | 选择订单后问 `能开发票吗` |
| 降价保护 | 付款后 168 小时内；比较同一商品历史实付与当前价；定制不参与 | 选择订单后问 `能保价吗` |
| 物流停滞 | 运输中 48 小时未更新可人工催件；已签收未收到需人工核实 | 选择订单后问 `物流不更新` |
| 无理由退货 | 订单状态、签收期限、商品属性、原售后政策版本 | 选择签收订单后问 `这单还能退吗` |

## 配置与流程

- `app/commerce/business_rules.json`：9 类新增规则，含版本、生效区间、店铺、渠道、商品范围、检索关键词、参数和条款说明。
- `app/commerce/policies.json`：原有无理由退货规则，保持兼容。
- `app/commerce/rules.py`：确定性规则判定、版本范围匹配、缺失信息处理。金额使用整数分计算。
- `check_business_rule`：统一只读工具，由本地执行器或经过签名的 MCP 调用。涉及订单时先验证归属。

商品与数量、普通/偏远配送区域可由用户明确提供；涉及具体订单时，金额、商品、付款时间和收货区域只能读取服务端订单数据。不会用聊天中的金额或区域覆盖订单记录，也不会把当前售价当成历史实付。

缺少数量或区域时支持追问，例如先问 `P200 买1件运费多少`，再回答 `普通区域`。同时问多类规则时会澄清，避免把优惠和运费的口径混算。

## 版本与历史订单

新生成的演示订单在 `details.rule_versions` 中记录适用版本。旧演示订单没有该字段时，按购买时间、店铺、渠道和商品类型匹配当时唯一有效的版本；已绑定但找不到的版本不会自动回退。缺少历史金额、付款时间或发票状态的旧订单会提示核实，可以注册新的测试账号体验完整字段。

新增规则版本时，必须给旧版本设置 `effective_to`，保持半开区间 `[effective_from, effective_to)` 不重叠，并同步更新条款说明与参数。启动时拒绝重复版本、重叠范围和无效参数。修改配置后需要重启 API 和 MCP。

## 操作边界

新增规则只提供查询与资格判定，未新增下单、发券、改价、改地址、开票或保价退款接口。原有取消订单、提交售后申请仍必须经过确认卡片。取消规则同时约束操作准备和最终提交，不能仅通过改提示词绕过制作状态或订单状态限制。
